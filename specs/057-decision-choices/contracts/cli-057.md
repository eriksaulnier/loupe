# Contract changes: `specs/001-loupe-v1/contracts/cli.md`

The implementation MUST apply these amendments to `cli.md`, each with a line that cites `specs/057-decision-choices`.

## Conventions: the PR-versus-local input table

Add a row. On a local run, `options` is accepted. On a PR run, it is refused with `input`. The message is "options apply only to local runs", and the fix is `use "suggestedFix" instead`.

## `loupe add`

The input finding MAY carry `options` in place of `proposal`:

```json
{
  "title": "Who invalidates an entry on a force-push?",
  "body": "…",
  "general": true,
  "options": [
    {"label": "Drop the cache on every push", "proposal": "…"},
    {"label": "Key the cache by head SHA", "proposal": "…", "recommended": true},
    {"label": "Let entries expire", "proposal": "…"}
  ]
}
```

Each refusal uses code `input` and names the rule. In a batch, it names the failing entry in `error.details.entry`.

| Input | Message names |
| :--- | :--- |
| Fewer than 2 or more than 3 entries | "options needs 2 or 3 entries" |
| No entry or several entries `recommended` | "exactly one option must be recommended" |
| Both `options` and `proposal` | "a finding has options or a proposal, not both" |
| `key` in an entry | the forbidden-field message, with `details.field` set to `options[N].key` |
| A label longer than 120 characters | "option label is longer than 120 characters" |
| An empty label or proposal | "option N needs a label and a proposal" |

The Markdown and `finding-id` refusals on a label or proposal keep their own codes (`markdown`, `finding-id`), as they do on `title` and `proposal`.

## `loupe edit`

`options` MAY be set, replaced or cleared with `null`. The shape rules apply to the finding after the edit. So an edit that adds `options` to a finding with a `proposal` MUST also send `"proposal": null`. A change to `options` clears the decision, and `clearedDecision` is true, as for any other field.

## `loupe show --json`

A finding carries `options` as stored, with each entry's `key`. A decision carries `choice` when it has one.

## `loupe feedback`

On a local run, an `apply` or `applyWithChanges` entry for a choice finding carries the picked option's proposal as `proposal`, plus `choice`: `{key, label}`. No entry carries `options`. The envelope stays `"loupe": 1`.
